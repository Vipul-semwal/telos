# Architecture Guide ? Telos Modular Monolith

## 1. Architectural Strategy

Telos is built as a **Modular Monolith**:
- Single unified deployable Next.js App Router application.
- Backed by an ACID-compliant PostgreSQL relational database.
- Completely separated internally into 9 domain modules:
  1. `auth`
  2. `disciplines`
  3. `projects`
  4. `tasks`
  5. `brain-dump`
  6. `daily-planning`
  7. `time-tracking`
  8. `reporting`
  9. `cockpit`
  10. `task-yard`
  11. `notifications`

## 3. Shared Notification Architecture

`notifications` owns the reusable scheduling engine. Sources such as standalone
Notify records and Task Yard recall cards create schedules through the same
service. The engine generates idempotent occurrences and delegates presentation
to a destination adapter; Cockpit is the only enabled destination.

```text
Notification source → schedule → occurrence → delivery → destination
```

Permanent source objects are never recreated when they become due. Flashcard
reviews are stored separately from occurrence delivery/read state.

## 3. Future Extensibility

Future modules will integrate directly as new siblings in `src/modules/`:
- `self`: Long-term psychological profiling and personal constitution.
- `learning-engine`: Skill acquisition trees and spaced repetition.
- `knowledge-management`: Conceptual notes and pursuit artifacts.
- `ai-intelligence`: Optional adapter layer for synthesis and reflection.
- `decision-engine`: Algorithmic next-action determination.

Because the core domain layer has zero dependency on AI SDKs, new modules can be plugged in without refactoring existing entities or tables.
